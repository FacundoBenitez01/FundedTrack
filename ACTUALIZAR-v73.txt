FUNDEDTRACK v73 — OPERACIONES Y CAPTURAS

QUÉ CAMBIA
• Loss guarda la pérdida con signo negativo aunque escribas 75. Win guarda el importe positivo aunque escribas -75.
• Lotaje opcional por operación: por ejemplo 0,10. Cada cuenta del grupo puede tener su propio lotaje.
• RR manual: podés escribir 1:2,5 o 1:4. La coma decimal se guarda como punto.
• Estado MOLESTO disponible en operaciones individuales y multicuentas.
• Hasta 3 capturas privadas por operación. Podés verlas y quitarlas al editar.
• En multicuentas, elegí Win o Loss para aplicar el signo a todos los importes. La opción inicial conserva el signo de cada cuenta. Las capturas comunes se suben una sola vez.

1. ACTIVAR LAS CAPTURAS EN SUPABASE
Extraé este ZIP en una carpeta.
Abrí ACTIVAR-CAPTURAS.sql con el Bloc de notas y copiá TODO su contenido.
Entrá a tu proyecto Supabase → SQL Editor → New query.
Pegá el contenido y pulsá Run. Comprobá que muestre Success.
Este SQL se puede repetir. Crea el espacio privado de imágenes y sus permisos; no modifica fundedtrack_workspaces ni tus cuentas.
No necesitás generar claves ni desplegar de nuevo las funciones de notificaciones.

2. ACTUALIZAR GITHUB
Abrí el repositorio FundedTrack → Add file → Upload files.
Subí index.html y sw.js de este paquete, reemplazando los anteriores en la raíz.
Pulsá Commit changes. Esperá que la publicación de Pages en Actions termine en verde.
Abrí la app, recargala y comprobá que Ajustes muestre v73. Si tenés la app instalada, cerrala y abrila nuevamente después de actualizar.
Los demás archivos del paquete son los recursos de la app; conservá los que ya están publicados.
No subas este ZIP como archivo: subí los archivos extraídos. El SQL y este instructivo se usan por separado.

3. PROBAR
Usá una cuenta de prueba.
Creá una operación Loss con importe 75, lotaje 0,10, RR 1:2,5 y estado MOLESTO.
Adjuntá una imagen pequeña y guardá. Comprobá que el P&L sea -75.
Editá la operación para comprobar lotaje, RR y captura.
Esperá la sincronización y abrí la misma cuenta de usuario desde otro dispositivo. Abrí Ver capturas.
Probá también Win y un grupo de cuentas, con lotajes diferentes.

SOBRE LAS CAPTURAS
Formatos: PNG, JPEG o WebP. Máximo 3 por operación y 12 MB por archivo de entrada.
La app reduce cada imagen a JPEG, hasta 1600 píxeles de lado y 1 MB.
La subida y la visualización necesitan Internet. Si falla la subida, el formulario sigue abierto y la operación no se guarda: corregí la conexión/configuración o quitá la captura.
Las imágenes se guardan en un bucket privado. La app pide enlaces temporales para mostrarlas al usuario propietario.
Los respaldos del diario contienen referencias a las imágenes, no los archivos de imagen. Para recuperarlas necesitás la misma cuenta y que los archivos sigan existiendo en Supabase.
Quitar una captura o borrar una operación no borra físicamente la imagen, para conservar referencias de grupos y respaldos. Los archivos retenidos ocupan espacio en Supabase Storage.

VALIDACIÓN
Probado localmente con Supabase y Storage simulados: signos, edición, lotaje, RR, capturas, error y reintento de subida, multicuentas, sincronización, límites y tamaños de pantalla.
El SQL y la subida real a tu proyecto requieren que completes los pasos anteriores; no se han ejecutado desde este paquete en tu Supabase real.
