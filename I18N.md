# JourFund language selector (v97)

Settings → Journal preferences → App language. The native dialog becomes a bottom sheet below 700 px. It supports Spanish, English and Brazilian Portuguese, keyboard dismissal, focus return, the selected appearance palette and reduced motion.

The existing protected workspace commit stores `preferences.language` and `preferences.languageChangedAt` on every current account. This uses the existing revision/conflict checks and synchronization queue; no SQL migration or new credentials are needed. The newest supported preference is restored when a workspace loads. Another signed-in user defaults to Spanish unless that user's workspace has a preference. Saving during an unresolved conflict or active sync shows the existing error and does not apply the selection.

`language.js` contains the initial UI catalog: navigation, common controls, core form labels, profile/settings, primary metrics and common statuses. Missing keys deliberately retain their Spanish source. Detailed program descriptions, less common validation text, native confirmations, date formatting, emails and server-generated push content are not fully localized by this release. Third-party charts/calendar content stays with its provider. This selector is not a claim of complete localization.

Stored values, journal notes, account/profile names, financial values, symbols and trade records are never rewritten by localization. The DOM adapter restores original text when returning to Spanish, observes newly rendered UI, and exposes `JourFundI18n.t(source)` for future explicit component localization. Prefer explicit dictionary calls as components are modernized. Do not translate user-authored content or use localized display text to make business decisions.

Verification: DOM tests for per-user preference isolation, reversible translation, dynamic statuses, preserving input/user records and rejection of failed saves; browser tests at 320, 390 and 1440 pixels with mocked authentication/workspace storage for selection, reload, cancellation and layout. This does not constitute a live Supabase end-to-end audit.
