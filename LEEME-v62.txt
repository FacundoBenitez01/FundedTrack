FUNDEDTRACK v62 — CENTRO DE NOTIFICACIONES Y WEB PUSH

QUÉ YA INCLUYE
Campana con contador y filtros; avisos de riesgo diario/pérdida máxima 70%, 90% y límite, ganancia objetivo y días mínimos, elegibilidad calculada de retiro opcional; alerta local de sincronización. Preferencias de avisos, horario y zona horaria. Push para Android y PWA instalada en iPhone iOS16.4+. Un botón envía una prueba real desde tu servidor. Cada usuario tiene su propio historial y dispositivos; cerrar sesión cancela la suscripción del navegador.
Las alertas usan los datos registrados y las reglas guardadas de la cuenta. No están conectadas al broker. Ganancia objetivo no implica aprobación ni retiro garantizado. No se muestran importes, cuenta ni correo en el mensaje externo. Los avisos de noticias económicas no están incluidos: requieren un proveedor de datos y licencia.

1. PUBLICAR LA APP (MISMO REPOSITORIO)
Abrí la carpeta app de este paquete. Subí TODO SU CONTENIDO al directorio raíz de FundedTrack en GitHub, reemplazando los archivos en un solo commit. No subas la carpeta app en sí. No subas el ZIP ni private.env. Esperá que Actions termine en verde y abrí https://facundobenitez01.github.io/FundedTrack/ . La campana y avisos internos funcionan con esa actualización. Las notificaciones externas todavía no estarán activas hasta los pasos 2–5.

2. PREPARAR LA BASE DE DATOS
En Supabase → SQL Editor → New query: pegá el contenido de supabase/schema.sql y pulsá Run. Es repetible: no elimina cuentas ni modifica fundedtrack_workspaces. Crea tablas privadas para preferencias, dispositivos, historial y cola de entregas. Acceso mediante funciones que verifican el JWT y restringen cada operación al usuario. La cuenta del servidor dispone de service_role dentro de Supabase; nunca en la app.

3. GENERAR Y GUARDAR LAS CLAVES (UNA SOLA VEZ)
Instalá Node.js versión LTS (18 o posterior) en tu PC. Extraé TODO este paquete en una carpeta propia. Abrí PowerShell/Terminal en esa carpeta (donde está generar-claves.cjs) y ejecutá:

node generar-claves.cjs

Creará private.env y activar-cron-privado.sql SOLO EN TU PC. No envíes esos archivos ni los subas a GitHub. No vuelvas a generar las claves al actualizar la app. Hacé una copia privada de private.env. VAPID_SUBJECT es el correo público de contacto del servidor; podés editarlo antes de instalar los secretos.

4. DESPLEGAR LAS DOS FUNCIONES
En la misma terminal ejecutá cada comando por separado:

npx supabase login
npx supabase link --project-ref ztkthcqjxptsxgtwfcfx
npx supabase secrets set --env-file private.env
npx supabase functions deploy push-api --no-verify-jwt
npx supabase functions deploy push-dispatch --no-verify-jwt

Login abre el navegador. El CLI puede pedir la contraseña de base de datos para link; usá la que creaste en Supabase. La app no usa esa contraseña.
--no-verify-jwt desactiva la comprobación antigua de la plataforma: push-api SÍ verifica el JWT real con auth.getUser antes de TODA acción. push-dispatch exige el secreto privado de cron. No permitas acceso anónimo cambiando esas comprobaciones.
No reemplaces SUPABASE_SERVICE_ROLE_KEY: Supabase la inyecta automáticamente dentro de la función. Si tu proyecto no dispone de esa variable automática, revisá los logs/configuración antes de continuar.

5. ACTIVAR EL ENVÍO PROGRAMADO
Abrí activar-cron-privado.sql que creó el paso 3 y pegalo en Supabase SQL Editor. Ejecutalo UNA VEZ. Guarda el secreto del programador en Vault y crea un trabajo cada minuto. Para repetir/cambiarlo, eliminá o actualizá el secreto existente ft_push_cron en Vault antes de ejecutar ese SQL; nunca publiques el secreto. El schema del paso 2 sí puede repetirse.
Verificá en Supabase Cron que fundedtrack-push existe y los resultados del HTTP en net._http_response muestran 200. Revisá Edge Functions → push-dispatch → Logs para errores. No dejes cron funcionando si detectás errores continuos. Para pausar:
select cron.unschedule(jobid) from cron.job where jobname='fundedtrack-push';

6. PROBAR EN EL TELÉFONO
Actualizá y abrí FundedTrack; iniciá sesión. iPhone: Safari → Compartir → Agregar a pantalla de inicio. Abrila desde ese ícono (iOS16.4+). Android: Chrome → Instalar app o agregar al inicio.
Ajustes → Notificaciones → Activar en este dispositivo. Permití los avisos. Pulsá Enviar prueba; bloqueá el teléfono y revisá el centro de notificaciones. “Servicio push aceptó” confirma la aceptación del proveedor; el teléfono decide cuándo mostrarla, según conexión, modos de concentración y ajustes.
El test tiene un límite de una vez por minuto. Cada usuario admite 5 dispositivos. Desactivar este dispositivo deja los otros activos.
Para probar con la PC apagada, activá Recordatorio del diario y un horario cercano con zona Paraguay. No registres una operación hoy; cerrá la app. El recordatorio se evalúa en la primera hora después del horario. No se envían recordatorios vencidos después de esa hora.
Para probar riesgo, creá una CUENTA DE PRUEBA y registrá una pérdida que alcance 70% de su límite diario. Esperá a que se sincronice. El servidor evalúa aproximadamente cada minuto; no equivale a vigilancia en tiempo real. No alteres cuentas reales para probar.

COMPORTAMIENTO Y LÍMITES
- No manda alertas de datos anteriores a la primera activación hasta que ese workspace se actualiza. Las alertas internas reflejan el estado actual.
- Deduplicación por usuario, cuenta, etapa, día y umbral; se conserva la alerta más alta al evaluar. No avisa dos veces por el mismo umbral. Reintentos de red usan el mismo tag; la entrega push es como máximo best effort, no garantía de una sola entrega en un fallo de red.
- Preferencias externas e historial se guardan en tablas privadas; avisos locales usan cache separado por usuario. Preferencias se guardan localmente si la función no está configurada, y se vuelven a guardar al activar el dispositivo.
- Datos no sincronizados NO pueden generar push en el servidor. La app muestra el aviso local de sincronización pendiente.
- Historial externo 90 días; se muestran últimos 100 avisos. Cola con máximo 5 intentos; suscripciones expiradas se eliminan. Cambiar claves VAPID exige reactivar cada dispositivo.
- Cron opera con lotes de 100 usuarios y hasta 50 envíos por ejecución. Es una primera versión para tu app: para cientos/miles de usuarios hay que separar evaluación y envío, paginar cola y controlar límites del plan, costos y tiempos de Edge Functions. No es un servicio de alertas de riesgo crítico.
- No se modifican el login, las cuentas existentes ni las paletas de colores.
- Validación hecha con navegadores y Supabase/push simulados, motor compartido y generación de petición Web Push cifrada. No se ejecutaron SQL/cron ni envíos en tu Supabase real; requieren tu despliegue.
